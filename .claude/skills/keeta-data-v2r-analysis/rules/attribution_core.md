## 三、异动判断标准

### 3.4 零值指标排除（全局强制）

当某指标本期和对比期均为 0（或 null），**不得用于任何方向的结论解读**——既不能判定为"稳定"、"持平"，也不能作为"无变化"的支撑证据。零值意味着数据不可用，而非"没有变化"。

### 3.0 ⛔ 基期健康度校验(最高优先前置闸门,强制)

**执行(在任何 Path 归因之前):**
`cxr_fetch.py` 默认已自动回溯近 ~10 周周度访购率序列,结果写在 JSON 的 **`baseline_health`** 字段。**归因前必须先读该字段,按 `verdict` 严格处理:**

| `verdict` | `pass` | 处理动作 |
|---|---|---|
| `baseline_ok` | true | 基期可信,正常进入 Path 归因 |
| `baseline_anomaly` | false | **对比期异常**。必须向用户说明"本次变化部分为均值回归",并**改用 `suggested_baseline` 推荐的前序正常周作为基期重跑**(`cxr_fetch.py --compare <suggested>`);重跑后才是真正要归因的问题 |
| `current_anomaly` | false | 本期异常、对比期正常。归因目标改为"本期为何偏离正常水位",而非"环比差多少" |
| `null`/`error` | null | 序列取数失败或样本不足,降级为人工看近 8 周趋势确认后再归因 |

- `pass=false` 时**不得直接拿原环比差值开跑归因**;必须先处理基期问题。
- `baseline_health.cyclicality_note` 非空时(如检测到 payweek/月末规律),需在归因时扣除该周期性成分,与 3.2 配合。
- 若用户明确要求"就按这个对比期看",可保留原基期,但**必须在结论中标注"对比期处于异常位,本次变化含均值回归成分"**。

### 3.1 异动阈值

| 对比类型 | 波动异常阈值 | 断崖阈值 | 长周期下滑 |
|---|---|---|---|
| WoW(7天) | ≥0.3pp | ≥1pp,或相对变化≥1~1.5%且有明显断点 | 连续≥4周持续下降 |
| DoD(单天) | ≥0.5pp | ≥1.5pp | - |
| PoP(N天,N≠7) | ≥0.3pp | ≥1pp | - |
| MoM(整月) | ≥0.2pp | ≥0.5pp | 连续≥3月持续下降 |

### 3.2 先排除规律性波动

进入归因前必须排除:Payweek 结束后回落(约 1pp)、季节/宗教节律(如斋月)、假期(开斋节/圣诞)、开城爬坡(新城前 4~6 周访购率低属正常)、周内效应(DoD 不可把星期结构差异误判为经营问题)。

### 3.3 DoD 专属检查

单天分析且用户未指定对比期时,必须先询问使用 DoD(前1天)/ WoW(前7天同星期几)/ 用户指定日期。若最终使用 DoD 且星期几不同,必须补做 weekday check:查过去 28 天逐天访购率 → 按星期几分组取均值 → 若差异 > 0.3pp,注明为结构性背景。

## 四、Path 0~5 诊断 SOP

执行顺序固定:**Path 0 → 1 → 2 → 3 → 4 → 5**,不得跳步。

> **⚠️ 下钻执行纪律(全局强制)**:执行任何下钻前必须:1 明确目标(哪个环节/Path/维度)→ 2 在本文档找到对应数据集和字段 → 3 优先用 `cxr_fetch.py --drilldown` 模式取数,禁止手动拼 origin_query 猜字段,禁止用其他 Path 缓存数据替代。

### Path 0:结构性因素与外部环境(每次必看)

- **大盘初观测**(60051984):访购率/DAU/交易设备数波动与趋势
- **结构性被动下跌**:DAU 是否因拉新/push/投放大涨;低访购率模块曝光占比是否抬升
- **外部环境**:天气(暴雨/台风/极端高温)、节日(Payweek/斋月/开斋节)、竞争(竞品大促)

影响机制链:
- 暴雨/台风(HK 黑雨)→ 商家停业 → 访购率暴跌;极端高温 → 外卖需求上升
- Payweek → 访购率 +1~2pp,结束后回落约 1pp
- 斋月 → DAU -25~40%,高峰转移至深夜;开斋节/圣诞 → DAU 大涨但结构性访购率下拉
- 竞品大促 → 低购买意图用户涌入,DAU 涨访购率跌

#### Path 0 附加:异常日检测(周期 ≥ 3 天时自动执行)

**触发条件**:分析周期 ≥ 3 天(排除单天 DoD 场景)时,Path 0 大盘初观测后自动执行本步骤。

**执行流程**:

1. **拉取逐天数据**:查询本期各天的日均访购率,使用 60051984 按天粒度取数
2. **识别异常天**:计算本期日均访购率和各天偏离值,满足以下任一条件即判定为异常天:
   - 单日访购率偏离本期日均 ≥ 2pp(绝对值)
   - 单日访购率偏离本期日均 ≥ 2σ(标准差)
3. **剔除重算**:若存在异常天,剔除该天(及对比期中对应的天),重算剔除后的本期日均访购率与对比期日均访购率
4. **判定规则**:
   - 剔除后 |周期访购率变化| < 1pp → 判断为"**异常日贡献为主**",整体波动主要由个别天驱动而非周期性趋势
   - 剔除后 |周期访购率变化| ≥ 1pp → 异常日非唯一因素,周期仍有整体性波动,继续正常归因流程

**`anomaly_day_check.verdict` 枚举值说明**:

| verdict 值 | 含义 |
|---|---|
| `no_anomaly_day` | 无异常日,整周性成立 |
| `anomaly_day_dominated` | 存在异常日且剔除后 |Δ| < 1pp,表观波动主要受异常日影响 |
| `insufficient_days` | 周期不足3天,跳过检测 |
| `error` | 检测执行失败,结果不可信 |

5. **输出**:
   - 在 Segment 1 的访购率段注明异常天及其表现(如"5/9(周六)访购率单日飙升至 40.8%,主因当日补贴脉冲")
   - 若判定为"异常日贡献为主":Segment 1 的访购率段使用以下模板表述异常日影响:
     `[日期]异常偏[高/低][X]pp,[稀释/放大]了真实[降/升]幅(剔除后 WoW [±Y]pp)。`
     其中:异常日正偏→"稀释",异常日负偏→"放大"。以剔除后Δ为真实趋势,后续归因基于剔除后Δ展开。
     Segment 1 尾部追加引导语:「如需下钻 [日期] 的异动原因,回复"下钻 [日期]"。」

**注意**:本步骤仅在 Path 0 阶段查逐天大盘访购率,不查其他 Path 的逐天数据。用户确认下钻某一天后,才对该天执行完整的 Path 1~5 归因流程。

### Path 1:供需关系

- **1A 需求质量**(数据集 62055197):按 `primary_access_channel_code` + `secondary_visit_channel_code`(一级+二级访问渠道)拆 DAU 和交易设备数,计算各渠道访购率,用贡献度公式拆结构贡献与效率贡献
- **1B 供给可得**(数据集 60051984):营业商家数 / 店均营业时长与访购率的相关性
- **1C 配送运力**(数据集 60051984):爆单缩减范围商家率 / ETA 均值与转化的相关性

影响机制链:
- 低质渠道引流↑ → 低访购率用户占比↑ → 大盘访购率结构性稀释
- 全渠道访购率同步下降 → 指向全局性因素(天气/大盘意愿),非渠道结构问题
- 营业商家数↓ → 搜索无结果率↑ → 搜索CTR↓ → 访购率↓
- 运力不足 → 爆单率↑ / ETA↑ → 用户下单意愿↓ → 提单转化率↓ → 访购率↓

### Path 2:价格因素(数据集 60048561)

- **补贴力度**:实付补贴率 / C补率 / 美补率 / 商补率,断点是否与访购率一致
- **补贴结构(首轮必查)**:按 `sales_type_name`(营销类型)/ `lifecycle_global_name`(生命周期)/ `actual_price_range_name`(客单价区间)下钻

关键字段:`actual_disc_ratio` / `actual_mt_charge_amt_ratio` / `actual_shop_charge_amt_ratio` / `actual_c_mt_charge_amt_ratio`

**价格信号(首轮必查,数据集 60051108 用增大盘)**:Path 2 除补贴率外,还必须查实付配送费与 AOV,对应 `price_signal` 任务:
- `actua_delivery_fee_per_order`:实付单均配送费(注:字段名拼写即为 `actua`,非笔误)
- `oavg_fin_actual_amt`:实付单均价 / AOV
- `oavg_orig_dlvr_fee`:原价单均配送费
- `oavg_charge_fee`:单均补贴金额

⚠️ **重要口径说明**:折扣率(`actual_disc_ratio`)反映补贴折扣幅度,**不等于实付价格**;配送费补贴收缩(实付配送费↑、原价配送费持平)不进折扣率口径,却直接拉高用户实付成本。**实付配送费与原价配送费的差值**是价格分析的关键信号,首轮必查,不可仅凭折扣率判断。

**补贴结构输出表格格式(必须遵守)**:分维度展开时使用以下表头,不得把补贴率列标注为"访购率":

| 营销类型 | GMV占比(基期→本期) | 补贴率(基期→本期) | 结构贡献 | 效率贡献 | **总贡献** |
|---|---|---|---|---|---|
| XXX | X%→X% | X%→X% | ±Xpp | ±Xpp | **±Xpp** |

影响机制链:
- C补感知最强(用户直接可见),C补下降 → 提单转化↓
- 从免运补贴转向优惠券/满减 → 用户提单页"免运"心智曝光减弱 → 感知补贴力度下降 → 提单转化↓
- 配送费补贴收缩 → 实付配送费↑(不进折扣率口径)→ 提单页实付变贵 → 提单转化率↓ → 访购率↓
- 补贴力度↑但访购率仍↓ → 说明转化瓶颈不在价格,需看其他路径

### Path 3:用户结构(数据集 60051984)

按新/老客(`is_new_user`)、设备类型(`os`)、语言(`device_language_code`)拆分访购率与 DAU 占比,用贡献度公式区分结构贡献与效率贡献。

结构变化规律:新客访购率低;Android < iOS;非当地语言用户↑需关注供给;T2 城市占比↑拖累大盘。若供需路径已定位为 DAU 变化驱动,用户结构通常是被动结果。

**⚠️ Path 3 强制要求**:用户结构分析**必须按§7.0双因素拆解计算贡献度**,禁止仅呈现各分层访购率变化幅度。输出格式(按|总贡献|降序,cxr_fetch.py 已自动计算):

| 分层 | DAU(基期→本期) | 访购率(基期→本期) | 趋势贡献(访购率自身变化贡献) | 结构贡献(DAU占比变化贡献) | **总贡献** |
|---|---|---|---|---|---|
| XXX | Xw→Xw(+/-N%) | X%→X%(+/-Xpp) | +/-Xpp | +/-Xpp | **+/-Xpp** |

结论必须给出:趋势贡献合计 vs 结构贡献合计哪个更大 → "效率驱动"还是"结构优化(被动)"。

### Path 4:流量分发

#### 主分析(首轮必做,数据集 60051984 + 62059514)

**止于模块级**:定位"哪个模块有问题"(曝光结构变化 vs 模块自身效率变化),不需进入模块内部。

**⚠️ 必须按§7.0贡献度归因**:各模块对大盘访购率的影响必须用双因素拆解(趋势=访购率变化×基期曝光占比,结构=曝光占比变化×(模块访购率-大盘访购率)),按|总贡献度|排序定位主因。禁止仅凭"访购率变化最大"或"曝光UV变化最大"归因。

典型场景:低访购率模块占比上升(结构负贡献);模块 CTR↑但访购率↓(落地承接差);AB实验/新模块上线挤占曝光。

搜索专属(数据集 60052643/60052634):搜索框 CTR 下降 = 分发问题;搜索内部转化下降 = 供给/算法问题。HK 用 `search_no_result_rate_new` 字段。

### Path 5:用户路径漏斗

#### 主分析(首轮必做,数据集 60051984)

**止于5步漏斗层**:输出各环节转化率变化及贡献度,定位主要漏损环节。不对环节再做子漏斗拆解。

| 漏斗环节 | 设备口径指标 | 用户口径指标 |
|---|---|---|
| DAU→进店 | 日均DAU-进店转化率(Uuid) | 日均访问-进店进品转化率(user_id) |
| 进店→提单页 | 日均进店-提单页转化率(Uuid) | 日均进店进品-提单页转化率(user_id) |
| 提单页→提单 | 日均提单页-提单转化率(Uuid) | 日均提单页-提单转化率(user_id) |
| 提单→支付 | 日均提单-支付转化率(Uuid) | 日均提单-支付完成转化率(user_id) |
| 支付→完单 | 日均支付-完单转化率(Uuid) | 日均支付完成-完单转化率(user_id) |

去重规则:若 Path 4 已定位模块异动,Path 5 的 DAU→进店环节直接引用 Path 4 结论,不重复分析。

**环节专属分析**:

| 环节 | 关键指标 | 关键问题 |
|---|---|---|

## 七、贡献度与结论强弱规则

### 7.0 ⚠️ 维度拆分必须用贡献度归因(全局强制)

**核心规则**:凡是按维度拆分分析率值型指标(访购率、转化率、CVR 等),**必须计算各维值的规模加权贡献度**,禁止仅凭"哪个维值变化 pp 最大"就判定主因。

**双因素拆解法(比值型指标通用公式)**:

设指标 X = B/C,维值 i 的指标值 x^i,分母 c^i(如进店UV、曝光UV),总分母 C = Σc^i:
```text
趋势贡献值(效率): t_x^i = (x1_i - x0_i) × (c0_i / C_0)
结构贡献值:       s_x^i = (c1_i/C_1 - c0_i/C_0) × (x1_i - X_0)
总贡献值:         d_x^i = t_x^i + s_x^i
验证:            Σ d_x^i = X_1 - X_0(误差 < 0.05pp)
```

**适用场景与分母定义**:

| 分析场景 | 指标 X | 维度 | 分母 c^i | 总分母 C |
|---|---|---|---|---|
| Path 1 渠道访购率 | 渠道访购率 | primary_access_channel_code + secondary_visit_channel_code | 渠道DAU(62055197.app_uv) | 总DAU |
| Path 2 补贴结构 | 分层补贴率 | lifecycle/sales_type/price_range | 各分层实付交易额(actual_pay_no_tip_gmv) | 总实付交易额 |
| Path 3 用户结构 | 分层访购率 | 新老客/设备/语言 | 分层DAU | 总DAU |
| Path 4 模块访购率 | 模块访购率 | ad_position_name | 模块曝光UV | 总DAU* |
| Path 5 下钻-入口CVR | 入口CVR | 页面×资源位 | 入口进店UV | 总进店UV |
| Path 5 下钻-商家维度 | 环节转化率 | shop_type_name | 商家类型进店UV | 总进店UV |
| Path 5 下钻-用户维度 | 环节转化率 | uuid_layers_3_name | 用户分层进店UV | 总进店UV |

*注:模块之间用户重叠(一人看多个模块),模块曝光UV之和 > DAU。公式仍以 DAU 为总分母 C(因为访购率 = 交易UV/DAU),模块贡献度合计可能 ≠ 大盘访购率变化(存在交互项误差),但排序仍有效。当模块贡献度合计与大盘偏差 > 0.3pp 时,需标注⚠️。

**Path 2 补贴结构贡献度**:补贴率(实付补贴率 = 补贴金额/实付交易额)双因素拆解的分母为**各分层实付交易额**(`actual_pay_no_tip_gmv`),脚本已自动查询并计算加权贡献度。

⚠️ **Path 1 渠道贡献度口径注意**:62055197(渠道数据集)与 60051984(大盘数据集)DAU 口径不同(渠道DAU之和可能 > 大盘DAU),贡献度合计与大盘偏差可能 > 0.05pp。偏差 > 0.2pp 时需在报告中标注⚠️并说明口径差异。

**输出要求**:
1. 报告中凡涉及维度拆分的结论,必须按贡献度(|d_x^i|)排序,而非按 pp 变化排序
2. 每个维值至少给出:`趋势贡献([指标名]自身提升贡献)` + `结构贡献([分母名]占比变化贡献)`,括号内替换为实际指标/分母名称(如"访购率自身提升贡献"/"DAU占比变化贡献")
3. 判定主因时,"贡献度最大"优先于"变化幅度最大"
4. 贡献度合计需与实际整体变化做一致性校验

**漏斗环节贡献度**(不适用双因素,单独公式):
```text
某环节贡献度 ≈ 该环节转化率变化(pp) × 基期其他所有环节转化率之积
```

> `cxr_fetch.py` 已自动计算所有贡献度,结果在 JSON 的 `contributions` 字段(`contribution_pp` / `structure_contribution_pp` / `efficiency_contribution_pp`),无需重新计算。

> **前置判断 Gate(强制执行)**:JSON 输出中的 `gate_checks` 字段包含脚本已计算好的前置判断,**分析前必须先读取,按以下规则严格执行**:
>
> | 字段 | `pass=true` | `pass=false` |
> |---|---|---|
> | `promo_zone_gate` | 正常分析 `drilldown_s2o_promo_pv` 数据 | **直接将 `analysis_conclusion` 字段文本原文输出,不得自行展开任何优惠专区指标** |
> | `submit_page_discount_amt_gate` | 正常解读提单页优惠金额变化 | **直接将 `analysis_conclusion` 字段文本原文输出,不得解读该指标变化比例** |
>
> `pass=false` 时禁止基于原始数据做任何推断,即使看到数值有明显变化。

### 7.1 主因排序原则

**核心原则:证据强度第一,贡献度辅助定量。** 漏斗贡献度和各 Path 的单点指标都是"定位工具"(告诉你变化集中在哪个环节/方向),不是归因结论。归因必须回答"它为什么变化",答案来自交叉验证与下钻,而非任何单一定位信号本身。

#### 两层归因决策框架(强制)

归因分两层,**定位**与**下钻**解耦,下钻对所有 Path 通用(不是漏斗专属):

**第一层 · 定位(对应 Segment 1)**
1. **Path 0 外部环境前置闸门**:先排查天气/节假日/赛事/竞对/政策/基础设施等外部事件。
   - 有显著外部事件且方向吻合 → 外部环境为主因或重要背景,内部归因须在"考虑/剔除外部影响"前提下进行
   - 无显著外部异常 → 进入下一步(无异常即省略,不在 Segment 1 展开)
2. **Path 1~5 + 漏斗交叉验证**:找出证据最强的候选方向(可能是补贴/用户结构/供给/模块/漏斗环节中的任意一个)。
   - 某方向指标与访购率同向、断点吻合、机制清晰 → 锁定为候选主因
   - 仅漏斗某环节贡献显著、而 Path 0~5 外部路径均无同向证据 → 锁定该环节为候选方向(根因待下钻)
   - 各方向均无清晰信号 → 进入情形 C(诚实保留)

**第二层 · 下钻(对应 Segment 2,按需触发)**
对第一层锁定的**任意方向**继续拆解到可行动的子原因(补贴→营销类型/生命周期/客单价;流量→渠道/资源位;供给→品类/商家分层;漏斗环节→入口/承接/技术指标)。
- 拆到可解释、可行动的子原因 → 升级为情形 A/B,明确主因
- 拆解后仍无清晰原因 → 情形 C,诚实保留

#### 主因判定(按"是否已下钻到可行动根因",不按贡献度大小)

- **情形 A(已定位 + 已下钻到根因)**:因果链闭合、方向一致、断点吻合 → **强证据,明确主因**,写"[根因指标变化] → [作用机制] → [影响的环节/大盘]"
- **情形 B(已锁定方向,但尚未下钻到根因)**:Segment 1 阶段只锁定到"哪个方向"(含漏斗环节自身),尚无内部子原因 → 诚实输出"主因方向锁定在 XX,根因待下钻",**触发第二层下钻**,不在 Segment 1 强行写死成因
- **情形 C(下钻后仍无清晰根因 / 证据不足)**:诚实输出"主漏损/主波动在 XX,但当前数据未定位到明确根因,需进一步排查 [方向]",**禁止为凑结论强行归因到某条 Path**
- 路径指标方向与访购率相反 → **反向信号,作为排除依据**;路径无显著变化 → **排除项**

**贡献度的正确用法**:
- 可量化时(如 STP、漏斗、入口):写"贡献约 Xpp",辅助说明量级
- 不可量化时(如供给爆单率、ETA、外部事件):只写方向判断和核心数字
- **禁止**:把"定位/现象"当归因结论。无论根因来自外部 Path、内部某 Path 还是漏斗环节自身,主因都必须回答"为什么变化",不得停留在"XX→XX 转化率下降了""补贴率下降了"这类现象层。
- 漏斗环节**可以**作为主因,前提是已下钻到该环节内部的具体原因(承接/入口/技术指标等),且 Path 0~5 交叉验证已排除外部及其他路径驱动。
- **何时锁定主因 / 何时标注待下钻**:Segment 1 阶段,只有某方向的根因凭常规取数即可闭合(如补贴率、渠道结构、供给指标)才写为确定主因(情形 A);若锁定的是需要细拆才能解释的方向(如漏斗环节内部、某模块内部),则按情形 B 标注"待下钻"。

不得仅依据某一指标变化最大(含漏斗贡献度最大)就认定主因;多路径解释力接近时可并列为"共同驱动"。**Segment 1 仅执行第一层(定位),不执行第二层下钻;下钻是用户回复「展开」或指定路径后的独立动作(Segment 2)。**

> **与§四取数顺序的关系**:§四的 "Path 0→5 不得跳步" 是**取数顺序**(所有 Path 数据都要拉齐);本节是**归因研判顺序**(按证据强度筛选主因)。两者不冲突:先全量取数,再按证据强度判断谁是主因。

**结论强度**:强结论(证据充分,可明确主因)/ 弱结论(方向明确但不能定量闭环)/ 暂无强结论(只有观察)。禁止为了报告好看把弱结论写成强结论。

**每条 Path 证据链必须覆盖四类**:支持证据(指标方向+断点)/ 反证(哪些数据不支持)/ 排除项(为何排除为主因)/ 不确定性(尚未闭环的环节)。
