# Hive SQL 生成规范

> 在第三段「分析详情」或用户要求生成 SQL 时，必须严格遵守以下规范，不得随意推断字段名或口径。

| 规范项 | 说明 |
|--------|------|
| 天分区 | `dt`，格式 `yyyymmdd`（**不带横线**），示例：`dt >= '20260318' AND dt <= '20260324'`，❌ 错误写法：`'2026-03-18'` |
| 小时分区 | `dt_hour`，格式 `yyyymmddhh`，范围写法：`>= '2026030100' AND < '2026040100'` |
| 地区过滤 | `WHERE region = 'SA'`（可选值：SA/HK/AE/QA/KW/BR/BH/OM） |
| 成单口径 | `is_arrange = 1` |
| 排除取消 | `status != 50` 或 `status = 40` |
| 金额单位 | 原始字段为最小辅币，展示时需除以精度换算（在 SQL 注释中说明） |
| 时间戳转换 | `from_unixtime(order_time / 1000, 'yyyy-MM-dd')` |
| Schema | 主要使用 `mart_sailor_global`（主数仓）和 `mart_sailor_finance_global`（财务），其他 schema 需先通过 `kdata table search` 确认存在 |
| SQL 方言 | **OneSQL（Hive 兼容）**，注意：字符串拼接用 `CONCAT()`，日期函数用 `date_format`/`from_unixtime`，支持 `IF()` 和 `CASE WHEN`，`CAST` 语法为 `CAST(x AS string)` |
| 字段未确认 | 若 ETL 代码未明确字段名，用 `/* 字段名 */` 占位并注明「需确认字段名」 |
| 比率指标 | 分母用 `NULLIF(..., 0)` 防止除零 |

## 🔒 分区字段强制限制规则

> ⚠️ **生成任何 SQL 前必须检查以下两条规则，违反则拒绝生成或自动补充条件。**

### 规则一：dt 分区必须显式限制

**前提：仅当 `dt` 是该表的分区字段时本规则生效。** 若表无 `dt` 字段，或 `dt` 不是分区字段（通过 `kdata table info <表名>` 确认，无 `[分区]` 标注），则无需添加 dt 过滤条件。

凡涉及 `dt` 为分区字段的表，**必须**在 WHERE 中加上 dt 过滤条件，禁止全表扫描。

- **用户未指定日期**：默认使用 **T-1**（离线数据最新一天）。
  由 Agent 根据**用户所在时区的 local 日期**推算，直接将日期字面量写入 SQL，**不使用 `current_date` 等 SQL 函数**（避免 Hive 服务器时区与用户时区不一致导致错误）。
  例：若用户时区为 Asia/Shanghai，当前为 2026-04-14，则 T-1 = `20260413`，写法：
  ```sql
  WHERE dt = '20260413'
  ```
- **用户指定了日期**：使用用户指定的值，格式 `yyyymmdd`（不带横线）
- **禁止**出现不带 dt 条件的全表查询，即使用户未提及日期也不可省略

同理，含 `dt_hour` **分区字段**的表，必须限制 `dt_hour` 范围，避免全表扫描；若 `dt_hour` 不是分区字段则无需限制。

### 规则二：region 分区必须显式限制

凡涉及含 `region` 或 `global_region_code` 字段/分区的表，**必须**在 WHERE 中加上 region 过滤条件。

- **用户明确指定了 region**：使用用户指定的值（如 `HK`、`SA`）
- **用户未指定 region**：
  1. 优先从对话上下文中推断（如用户之前提到 HK、BR 等）
  2. 若无法推断，**询问用户**，禁止默认查全区域或省略 region 条件
  3. 如用户明确要求查全区域，写法：`AND region IN ('SA', 'HK', 'AE', 'QA', 'KW', 'BR', 'BH')`，并在注释中注明「需确认用户是否有所有区域的权限」

> 可选 region 枚举：`SA`（沙特）/ `HK`（香港）/ `AE`（阿联酋）/ `QA`（卡塔尔）/ `KW`（科威特）/ `BR`（巴西）/ `BH`（巴林）/ `OM`（阿曼）

### 其他分区字段

若表存在除 `dt`/`dt_hour`/`region` 以外的其他分区字段（通过 `kdata table info <表名>` 查字段时标注了 `[分区]`），同样**必须**在 WHERE 中加上对应过滤条件，避免全表扫描。

> **判断是否为分区字段的方法**：执行 `kdata table info <表名>`，字段名后有 `[分区]` 标注的才需要强制过滤；普通字段（无标注）不受本规则约束。

---

**SQL 输出格式要求：**
- 必须包含注释说明指标口径、数据来源表、分区条件
- GROUP BY 和 SELECT 中的维度保持一致
- 生成后明确标注：「⚠️ 此 SQL 为参考模板，字段名需结合 ETL 代码或 query.py info <表名> 确认后再执行」
