# 输出格式规范

> ⚠️ **[MANDATORY]** 本文件中所有带 ⚠️ 或 🚫 的规则为**强制执行红线**，AI 模型不得以任何理由跳过、省略或简化。违反任何一条等同于输出不完整报告。

## 🚨 最高优先级输出规则（用户确认，2026-06-11，不可违反）

> **这是用户明确要求的输出方式，优先级高于一切内部规则。**

**一、每个模块必须独立、按顺序输出（严禁偷懒）**
- 营业情况 → 体验质量 → 活动参与 → 流量渠道 → 商家补贴，五个模块缺一不可
- 每个模块内部的子维度同理：营业情况的层152必须都输出；流量渠道的曝光UV和CTR必须都输出
- 🚫 **禁止以「汇总见下方」、「详情略」、「正常无需赘述」等话语代替完整输出**

**二、无异常必须写「无异常」 + 一句说明**
- 正确：「✅ 无异常。店均出餐 12.83min，WoW +0.08%」
- 错误：直接跳过该模块不写，或将多个模块共用一句话带过
- ud83d� **禁止一占就跳过整个模块不写**

**三、有异常必须按该模块逻辑完整下钓**
- 营业情况异常 → 门店级列明细表格
- 出餐超阈值 → 门店级列明细表格（shop_id/门店名称/负责人/出餐当期/出餐对比期/WoW）
- 流量曝光下降 → 先拆解7个资源位汇总表，再门店级明细
- 流量 CTR 下降 → 先给 7 个资源位分渠道 CTR 表，再门店级明细
- 商补下降 → Top10 降幅最大门店表格
- ud83d� **禁止只写结论不写明细，禁止写「详情见附件」**

**四、输出顺序**
```
品牌标题（标色 + 操单量 + WoW + 大盘贡献）

营业情况
  └─ 层1：WoW同比（无异常就写无异常，有异常就列门店明细）
  └─ 层2：在线未营业门店（无论层1是否异常，必须查并输出）

体验质量
  └─ 出餐时长（无异常就写无异常 + 数值，有超阈值门店就列明细）
  └─ 商责取消（取消率 + 取消量，两个都要写）

活动参与（无异常就写无异常 + 数值）

流量渠道
  └─ 曝光UV（品牌级总起，有下降就拆解7资源位 + 门店级明细）
  └─ CTR（品牌级总起，有下降就拆解7资源位 + 门店级明细）

商家补贴（无异常就写无异常 + 数值，有下降就列 Top10 门店）

综合结论（每个品牌必须有）
```

## 🚫 强制执行红线（AI 不得违反）

以下规则为最高优先级，**优先于任何"内容太长"、"已有汇总"、"用户应该已知道"等理由**：

### 红线1：五个维度必须全部输出
- ⚠️ **营业情况 / 体验情况 / 活动参与 / 流量分析 / 商补情况 — 五个维度缺一不可**
- 无异常时：必须写明"无异常"并给一句说明，例如「出餐时长正常，均值 12.3min，WoW +1.2%」
- 有异常时：必须输出完整门店明细表格（见截断规则）
- 🚫 **禁止以"该维度正常，不赘述"、"无明显变化"等模糊话语代替完整输出**

### 红线2：指标名称必须用数据集官方名称，且必须使用用户对话语言对应的版本
- ⚠️ **禁止自创缩写或别名；禁止随意翻译中文指标名；禁止在英文/葡语环境下直接展示中文名**
- 指标名称必须查 `sql-templates.md` → `## 指标多语言名称对照表`，按用户语言选对应列（English / Português (BR)）
- `—` 的条目退而使用 English 列的名称
- 🚫 错误示例（英文环境）：直接展示"曝光→进店转化率"、自译为"CTR rate"、"exposure conversion"等
- ✅ 正确示例（英文环境）：使用 `Merchant Entry Exposure -> Homepage Expose Rate (CTR)`

### 红线3：综合结论必须输出
- ⚠️ **每个品牌的报告必须以"综合结论"结尾**，包含：
  1. 核心根因（一句话总结最关键问题）
  2. 问题严重程度判断（多少家门店、什么比例受影响）
  3. 建议跟进人 + 跟进方向
- 🚫 **禁止省略综合结论**，不允许报告直接以明细表格结尾而无结论段落

### 红线4：多品牌时每个品牌必须完整输出
- ⚠️ **多品牌分析时，每个品牌必须单独输出完整诊断报告**
- 🚫 禁止用"参见上方"、"与第一个品牌类似"、"汇总见下方"代替单品牌完整内容
- 🚫 禁止因品牌数量多而压缩或省略某个品牌的门店明细
- 品牌数量不是偷懒的理由，5个品牌就要5份完整报告

### 红线5：多品牌分析完成后一次性发汇总
- ⚠️ **多品牌并行分析时，等所有品牌跑完后一次性发汇总，不要逐品牌分批发**
- 汇总最上方加外部环境参考（天气/节假日/大型活动）
- 各品牌完整报告依次排列，品牌间用 `---` 分隔线区分，最后追加跨品牌问题门店清单

### 红线6：营业情况两层判断必须独立输出
- ⚠️ 营业情况分两层，二者**独立判断、独立输出，不可互斥**：
  - **层1 WoW 同比**：有异常则列异常门店明细；无异常则写"无同比异常"
  - **层2 当期在线未营业**（`is_online_shop=1 AND is_open_shop=0`）：**无论层1是否异常，都必须执行并输出**；有则列门店明细；无则写"无在线未营业门店"
- 🚫 禁止只输出一层、或以层1结果代替层2

### 红线7：门店明细超过10家时的截断规则
- ⚠️ **超过10家异常门店时，先输出前10家，再提示用户是否需要完整列表**
- 截断不等于省略：必须先有完整的明细数量说明（如"共 23 家门店异常"），再截断到前10
- 🚫 禁止因"太多了"就跳过整个维度的明细

### 红线8：从文件读取后整合发送，不得压缩内容
- ⚠️ 从文件读取中间结果后发送时，**必须完整输出原始报告内容**（含所有门店明细表格）
- 🚫 禁止将完整报告压缩为"关键指标摘要"发送
- 🚫 禁止省略门店明细，以"门店详情见附件/文件"代替输出

### 红线9：前线角色不得触发大盘监控
- ⚠️ **前线 BDM/BD（角色选项2/3）不具备大盘权限**，不得查询整个 Region 所有品牌的排名或波动贡献
- 若前线用户在分析过程中提出"大盘怎么样"、"整体 Top X"、"波动贡献最大的品牌"等大盘相关问题，**必须直接拦截**，回复：
  > 「你当前角色无大盘权限，无法查询全局品牌排名。请使用定向分析A（按指标排序）或定向分析B（指定品牌id）。」
- 🚫 禁止在前线角色下静默执行大盘监控查询

### 红线10：多品牌分析必须逐品牌顺序完整输出，不得交叉
- ⚠️ **多品牌分析时，先完整输出第1个品牌的所有五模块 + 综合结论，再开始第2个品牌**，依此类推
- 🚫 禁止将多个品牌的分析内容交叉混排（如先列所有品牌的营业情况，再列所有品牌的体验情况）
- 🚫 禁止先发一张跨品牌汇总表，再补充"各品牌详情如下"
- 正确顺序：品牌A（五模块完整 + 结论）→ 品牌B（五模块完整 + 结论）→ ... → 跨品牌汇总

### 红线11：角色一旦选定，全程固定，不得因用户描述而临时切换
- ⚠️ **用户在第零步选定角色后，该角色贯穿本次分析全程**，不因后续任何描述（如"帮我看一下大盘"、"我其实是后线"）而切换工具或开放权限
- 若用户中途要求切换角色或访问超出当前角色权限的功能，**必须提示重新走第零步**：
  > 「需要切换角色请重新选择：[展示角色选项]」
- 🚫 禁止静默切换工具（如前线角色中途改用 keeta-data-query 执行 Hive SQL）
- 🚫 禁止因用户"临时说明"而推断其实际角色并升权

## 输出顺序规则

- 各维度**固定按顺序**输出：营业情况 → 体验情况 → 活动参与 → 流量分析 → 商补情况
- **禁止使用"模块1/2/3/4/5"等内部编号作为标题**，统一使用业务语言标题
- 每个维度标题格式：**`**营业情况**`**（加粗），下方紧跟内容

## Step 0 指标状态标记规则

- 🔴：WoW 变化超过阈值（订单 ≤-30%、出餐 ≥+50%、商补 ≤-30%、商责 ≥+50%、转化率 ≤-20%）
- 🟡：WoW 变化中等（订单 -10~-30%、出餐 +20~+50%）
- ✅：正常无异常
- 若指标无数据（如该品牌无商补），显示 — 不标色

---

## 颜色规则（品牌标题）

- 🔴 红：订单 WoW ≤ -30% 或存在严重供给问题
- 🟡 黄：订单 WoW -10% ~ -30% 或问题待确认
- 🟢 绿：订单 WoW > -10% 或无明显异常

## 各维度详细输出规范

### 营业情况（必须包含两层，均需输出）

**层1：WoW 同比**
- 异常阈值：营业时长 WoW < -10% 或在线门店数 WoW < -5%
- 有异常 → 输出明细表格：

| shop_id | 门店名称 | 负责人 | 异常类型 | 营业时长（当前）| 营业时长（上周）| WoW |
|---------|---------|--------|---------|--------------|--------------|-----|

- 无异常 → 写：「营业时长同比正常，均值 XX.Xh，WoW XX%」

**层2：当期在线未营业**
- 查询条件：`is_online_shop=1 AND is_open_shop=0`（当期数据）
- ⚠️ 无论层1是否异常，都必须执行此查询
- 有结果 → 输出明细表格：

| shop_id | 门店名称 | 负责人 | is_online_shop | is_open_shop | 备注 |
|---------|---------|--------|---------------|-------------|------|

- 无结果 → 写：「无在线未营业门店」

---

### 体验情况（出餐时长 + 商责取消）

**出餐时长：**
- ⚠️ **方向说明（易错）**：出餐时长是"越低越好"指标。MoM 下降 = 改善 ✅，上升才告警。Step 0 品牌级汇总的状态标注同理，禁止将 MoM 负值标为 🔴。
- 异常阈值：门店级出餐时长**绝对值 > 15min OR WoW > +10%**（满足任一即为异常，两个条件独立判断）
- 有异常 → 输出明细表格：

| shop_id | 门店名称 | 负责人 | 出餐时长（当前）| 出餐时长（上周）| WoW | 订单 WoW |
|---------|---------|--------|--------------|--------------|-----|---------|

- 无异常 → 写：「出餐时长正常，均值 XX.Xmin，WoW XX%」

**支付成功后商责取消：**
- ⚠️ 指标名称必须严格使用数据集官方名称（**按用户语言从多语言对照表取对应版本**）：
  - 取消率 code: `paid_order_cancel_rate_merchant_reason`（中文：支付成功后商责取消率（商家责任）；英文：Post-payment order cancellation rate (merchant responsibility)）
  - 取消量 code: `paid_order_cancel_num_refund_shop_res`（中文：支付成功后订单取消量（商家责任）；英文：Number of post-payment cancelled orders (merchant responsibility)）
- 必须同时输出取消率（pp）和取消量（单数），不得只输出其中一个
- 输出格式（中文）：「支付成功后商责取消率（商家责任）：当期 X.XX% vs 对比期 X.XX%，PoP XXpp；支付成功后订单取消量（商家责任）：当期 XX 单 vs 对比期 XX 单，PoP XX%」
- 输出格式（英文）：「Post-payment order cancellation rate (merchant responsibility): current X.XX% vs prev X.XX%, PoP XXpp; Number of post-payment cancelled orders (merchant responsibility): current XX vs prev XX, PoP XX%」
- 有恶化（取消率 PoP > +10pp 或取消量 PoP > +20%）→ 必须补充取消原因分布，规则如下：
  - **所有角色**：**必须**执行 `step2_cancel_reason_query`（数据集 62059636）获取门店级取消原因分布，按原因+数量+占比输出，不可省略。**前线/后线均可执行，不再依赖 Hive 权限**。

### 活动参与（满折 + 折扣菜）

- 输出品牌级覆盖率：满折 XX%（上周 XX%），折扣菜 XX%（上周 XX%）
- 有下降（覆盖率 WoW < -5pp）→ 输出失效门店明细：

| shop_id | 门店名称 | 负责人 | 满折当期 | 满折上周 | 折扣菜当期 | 折扣菜上周 |
|---------|---------|--------|---------|---------|----------|----------|

- 无下降 → 写：「活动覆盖率正常，满折 XX%，折扣菜 XX%，无明显变化」

### 流量分析（曝光UV + CTR，两块独立输出，严格按顺序）

> ⚠️ 流量分析**无论是否异常都必须输出**（正常时写"无异常"并给数值，不跳过）。
> ⚠️ 分为**两块**，必须先看曝光UV，再看CTR，不得合并或颠倒顺序。
> ⚠️ "触发下钻"仅决定是否输出门店级明细，不影响品牌级曝光UV和CTR汇总表的输出义务。

## 多品牌分析时的输出规则

当分析多个品牌（Top3 或 Top10）时：
- **每个品牌必须单独输出完整诊断报告**，包含 Step 0 总览 + 五个维度完整内容 + 综合结论
- **禁止在汇总时压缩、省略任何品牌的门店明细**，不允许以"参见子报告"代替实际内容
- 品牌之间用 `---` 分隔线区分
- 所有品牌完整报告输出完毕后，最后追加「跨品牌汇总」
- ⚠️ **多品牌不是偷懒的理由**：品牌数量多时，每个品牌的报告都要完整，不能因为"已经有汇总了"就省略单品牌内容
- ⚠️ **统一发送**：等所有品牌跑完后一次性发汇总，不要逐品牌分批发；汇总最上方加外部环境参考
