# 交付模板(Segment)

### ⛔ 输出边界(全局强制)

**只输出格式化结论,禁止输出中间过程。** 用户可见内容仅限 Segment 1/2/3 格式化报告,严禁将以下内容作为用户可见输出:
- 数据汇总表、原始 JSON、查询中间结果
- 中间推理或过渡语句(如「现在我来分析...」「接下来看 Path X...」「让我拉取数据...」)
- 脚本执行日志、调试信息

若用户主动请求查看原始数据,仅以 Segment 2 展开形式呈现关键数据表,不暴露完整中间过程。

**§3.0 基期校验输出规则(强制)**:
- `verdict = baseline_ok` → **完全静默**,Segment 1 不得出现任何基期校验相关文字(无表格、无 z-score、无近N周幸标语句)
- `verdict = baseline_anomaly / current_anomaly / null` → 仅一句说明异常情况,不展开过程(如"对比期访购率异常偏高,建议按平常水位 XX周对比")

### 10.05 ⚠️ 归因决策(MUST - 写 Segment 1 之前强制执行,不输出给用户)

取数完成后、填写 Segment 1 模板前,必须先完成以下决策步骤:

| 步骤 | 操作 |
|---|---|
| 1. 漏斗定位 | 读漏斗贡献度,标记贡献最大的 1~2 个环节 |
| 2. 交叉验证 | 对每个定位环节,检查 Path 0~5 哪些指标与该环节方向同向、断点吻合、机制清晰 |
| 3. 机制链 | 若找到同向外部 Path → 写出 [根因指标变化] → [作用机制] → [影响的环节] |
| 4. 判定情形 | 按 §7.1 情形 A/B/C 判定:有外部根因闭合→A;仅锁定方向→B;无清晰信号→C |
| 5. 写归因 | 按对应情形模板填写归因段 |

**规则:**
- ⛔ 禁止跳过此步骤直接填写归因段
- 归因段的主因必须来自步骤 3 的机制链输出,不得直接使用步骤 1 的漏斗定位作为结论
- **漏斗环节可以作为主因的唯一条件**:步骤 2 交叉验证后 Path 0~5 均无同向根因 → 按情形 B 输出("主因方向锁定在 [环节],根因待下钻"),或已下钻到该环节内部子原因后按情形 A 输出

### 10.1 Segment 1(首次回复)

> **[MANDATORY] 格式约束**:触发 Segment 1 时,必须严格按本节模板格式逐段输出,不得替换为自由总结或自定义结构。每个槽位(访购率、归因、补贴、供给/运力、漏斗等)必须独立成段,不得合并或省略有数据的段落。

**风格要求**:段落式结论,按分析主题组织。每段简短,**每句话只讲一个要点**;同一要点下可罗列多个相关指标(如补贴力度的多个维度),但禁止把不同要点的指标硬塞到一句。第一句给结论 + 关键数字,后续句给因果方向、异常信号或补充要点。超出本段核心结论的细节移至 Segment 2,禁止截断半句。

**排版要求**:
- 每段的**关键变化量加粗**(如 `**+1.65pp**`、`**-3.7%**`),让读者扫一眼就能抓到核心数字
- 归因段写自然段落式结论,直接写核心结论 + 证据数字,多条原因时按"核心原因→辅助因素→反向信号"顺序组织。允许自然标签区分层次(如"主因:""辅助因素:""反向信号:"),但不用固定模板。
- 归因必须是"根因 → 机制 → 影响环节"结构,不得以"漏斗环节变化"开头(详SKILL.md §7.1、本文件 §10.05)

```md
## [地区] [设备/用户]访购率异动分析 · [本期周期]
> 本期:MM/DD~MM/DD | 对比期:MM/DD~MM/DD(WoW/DoD)

**[设备/用户]访购率:** X% → X%(**±Xpp**),[判断]。[异常日/剔除后结论(如有)]。

**归因:** [1~3 句自然段落:根因 → 机制 → 影响环节 + 关键数字]
  ← 若仅锁定方向未到根因,改用情形 B 写法("主因方向锁定在 XX,根因待下钻");证据不足用情形 C。详上方三种写法

**外部环境:** [有影响因素时写具体事件+影响;无特殊事件时写"无特殊外部事件"]。

**需求/渠道:** [organic/marketing DAU 占比变化;按一级+二级渠道给出主要拉动/拖累渠道及贡献(±pp);无异动时写"渠道结构稳定,无异动"]。

**补贴:** [总补贴率变化 + 结构转移方向]。[与访购率方向是否一致]。

**供给/运力:** [逐项列出营业商家数、店均营业时长、ETA、搜索无结果率、置休率、超区率的变化;零值指标(两期均为0)不输出;全部无异动时可合并为一句"供给侧稳定,非驱动因素"]。

**用户结构:** [列出主要维值(含占比、访购率、效率贡献、结构贡献),按影响大小排列,串联说明波动来源。影响分散的维度一句话带过。详细拆解在展开/下钻时呈现]。[属 Path 3,不得与「需求/渠道」混用]。

**流量分发:** [主要拉动/拖累模块 + 贡献 **±Xpp**]。[数据异常模块需注明]。[无异动时写"各模块流量分发稳定,无异动"]。

**漏斗:** [主要拉动/漏损环节 + 贡献 **±Xpp**]。[次要环节(如有)]。

---
回复「展开」查看各路径完整诊断,或直接指定路径下钻。
```

**约束**:
- 每段简短,**每句话只讲一个要点**;同一要点下可罗列多个相关指标,但禁止把不同要点的指标硬塞到一句。细节移至 Segment 2,禁止截断半句
- 无异动的路径不得省略整段,必须有"查了但无异动"的明确表述(如"供给侧稳定,非驱动因素");多个无异动路径可合并为报告末尾一句汇总(如"外部因素无特殊事件,渠道来源、流量分发模块无异动变化")
- 证据不足时用"候选主因/主因方向待下钻"表达,禁止伪装强归因
- **主因不得是现象描述**:不得以"某环节转化率下降""补贴率下降"这类定位/现象作为主因收尾;若主因是漏斗环节自身,需有该环节内部下钻证据支撑(详SKILL.md §7.1)
- **每句话必须同时有数字和判断**:只有逻辑没有数字(如"这是被动效果")、只有数字没有判断(纯罗列指标)均不合格;删掉而不是保留
- **禁止出现分析框架术语和仪式性文字**:Path 编号、"证据闭环"、"因果链闭合"、"被动效果"、"暂无额外发现"、"数据完整"等一律不得出现在结论中
- **统一使用"访购率"表述**:输出中统一写"访购率"或"设备访购率"/"用户访购率",不使用英文缩写
- **校验类信息只在异常时呈现**:贡献度一致性等内部质量检查通过则不写,仅异常时注明(如贡献度偏差 >0.3pp)
- **异常日引导**:若 Path 0 异常日检测判定为"异常日贡献为主",访购率段使用模板:
  `[日期]异常偏[高/低][X]pp,[稀释/放大]了真实[降/升]幅(剔除后 WoW [±Y]pp)。`
  正偏→"稀释",负偏→"放大"。以剔除后Δ为真实趋势,后续归因基于剔除后Δ展开。
  在 `---` 分隔线之前追加:「如需下钻 [日期] 的异动原因,回复"下钻 [日期]"。」

### 10.2 Segment 2(展开后)

按 Path 0~5 逐条展开,每条 Path 格式:

```md
**Path X [名称] · [高/中/低]相关:** [结论段落,含核心数据 + 判断方向 + 支持证据]。[反向信号(如有)]。[不确定性(如有)]。
```

数据表仅在需要呈现多行对比时使用(如漏斗5步、补贴多维度),不为了格式统一而强加表格。

### 10.3 Segment 3(紧接 Segment 2)

根据本次分析中**高/中相关的路径**,动态生成下钻建议。禁止写死固定示例。

格式:
```md
如需下钻,建议优先关注:
- 「[根据实际高相关路径生成,如:拆解提单页→提单环节的优惠感知变化]」
- 「[根据实际中相关路径生成,如:看弹窗模块效率下降原因]」
```

约束:
- 建议项必须来自本次分析结论中相关性为高或中的路径/环节
- 每项用具体的分析方向描述(不是泛泛的路径名),让用户知道下钻后能看到什么
- 若所有路径均低相关,仅提供建议但不做限制:「本次各路径波动均较小,如有感兴趣的方向也可以告诉我。」

**Follow-up 纪律**:后续追问必须真的进入下一层(Path 级 → 子环节级 → 更细维度),禁止同一层指标换说法复述或只把结论拆长。用户可直接指定 Path 或子环节,不要求先走"展开"步骤。

### 10.4 下钻分析输出格式(进店→提单页 / 提单页→提单)

**呈现顺序**(固定,不得调换):
1. 加购拆解
2. 优惠感知(`gate_checks.promo_zone_gate.pass=false` → 整段不展示,直接跳到下一项)
3. 用户分层
4. 商家类型
5. 品类
6. 入口来源

每项格式:`**[视角名]**:[结论 + 关键数字]。[异常信号或方向(可选)]。`,最多 2 句,不用标题序号。

**综合判断**:1~2 句,点出主因 + 最重要的支撑数据。不用"背景因素/机制尚未闭环/值得关注"等套话,直接说是什么、数有多大。

**输出标准要求**:
- 率值变化只写 pp 绝对变化(如 -0.73pp),禁止写相对百分比
- 每个维度必须带 UV 量级,无量级的结论不得作为主因
- **维度拆分必须给出贡献度**(SKILL.md §7.0):按|趋势贡献+结构贡献|排序呈现各维值,综合判断基于贡献度排序而非变化幅度排序
- gate 判断为 false 的视角整段不展示,不写"跳过"说明
- 不出现验证类语言("证据闭环"、"一致性通过"等),异常信号直接描述
- 综合判断不重复罗列各视角数据，只提最关键的 1~2 个支撑点（以贡献度最大的维值为准）

### 10.5 缺失依赖 Skill 提示（条件输出）

当取数结果 JSON 中存在 `missing_skills` 字段（非空数组）时，在报告末尾（Segment 1 的 `---` 分隔线之后）追加提示：

```md
⚠️ 以下可选 Skill 未安装，部分分析维度已跳过：
- **{skill名}**: {impact描述}。{install_hint}
```

规则：
- 仅当 `missing_skills` 非空时输出，空数组或无该字段则不显示任何内容
- 每个缺失 skill 单独一行，包含 skill 名称、影响范围、安装提示
- 不影响主流程分析输出，仅作为末尾补充信息
